# Refinement criteria

Phase 2's rubric. Weigh the dimensions that matter for the idea.

## 1. User value

A painkiller (an acute, frequent problem people already work around) or a vitamin (nice to have). The real competitor is the current workaround.

**Red flags:**
- "Everyone could use this": no specific user, so the value isn't clear.
- "It's like X but better": marginal improvements rarely drive adoption.
- The problem is real but rare: high intensity at low frequency rarely justifies a product.

## 2. Feasibility

Can it be built, technically and practically, and how soon does it reach users?

**Red flags:**
- "We just need to solve [very hard research problem] first."
- Several dependencies that all need to work at once.
- The MVP still takes months: not minimal enough.

## 3. Differentiation

What makes it different, not just better, and can a competitor copy it in a week?

**Types, strongest to weakest:**
1. **New capability:** does what was impossible.
2. **10x improvement:** so much better on a key dimension that it changes behaviour.
3. **New audience:** brings an existing capability to people who were excluded.
4. **New context:** works where existing solutions fail.
5. **Better UX:** the same capability, a much simpler experience.
6. **Cheaper:** the same thing at lower cost (easily competed away).

**Red flags:**
- The difference is all technology, none user experience.
- "We're faster/cheaper/prettier" with no structural reason.
- The differentiating feature is not the one users care most about.

## Assumption audit

Each direction's assumptions, in three kinds:

- **Must be true:** wrong, it kills the idea. Validate before building.
- **Should be true:** wrong, the approach changes but the idea survives.
- **Might be true:** secondary. Validate once the core is proven.

The **deadliest assumption** is the must-be-true most likely to be wrong.
